# 交付地图共用更新流程

集管和网管执行同一流程。先按 [产品差异配置](products.md) 选择产品，操作范围限定在用户本次指定的产品。

## 确定输入

读取工作区和产品目录规则、README、实际生成脚本。定位用户本次提供的月度《进度跟踪表》、已有调度体系骨架和地图；文件名以实际目录为准。使用表内统计月份，格式 `YYYY-MM`，有歧义时结合用户说明确认。

每次以用户提供的最新表格更新。在线数据源地址和显示名称从用户指示、产品目录本地配置读取；缺少配置时检查现有地图及模板，仍无法确定再询问。具体业务文档地址、客户表格、内网地址和配置留在产品工作区，不写入插件或 README。无需自动访问在线内容。

页面沿用对应产品的固定数据源入口，来源链接不随月份或本地文件名变化。外部链接用新标签打开，并设置 `rel="noopener noreferrer"`。保留已有地图、统计、提示和下钻；项目核对依据保存在本地。产品特有的页面约束见 [产品差异配置](products.md)。

## 检查项目与字段

使用具备 `openpyxl` 的 Python，执行共用只读检查脚本：

```bash
<python> <插件根目录>/scripts/delivery-map/inspect_tracking.py '<月度表.xlsx>' --product '<集管或网管>' --sheet '<实际工作表>' --backbone '<按调度体系.xlsx>'
```

检查表头、缺列、空客户、重复项目、新客户、未出现的历史客户和多行映射。输出仅用于本地核对，不作为地图页面内容。工具成功退出后仍须检查未映射项目与历史保留记录。

按 [数据规则](data-rules.md) 核对业务归属。已有同一项目的多行映射全部更新。更名须有明确依据；新项目复用已核对的地理行。重复且有冲突、落点被占用、公式无缓存、未确认地理归属等问题处理前不发布。

## 合并与重建

修改前查看 Git 状态，保留可回退提交或备份，保留用户未提交改动。原始输入表不修改。现有 HTML 可能存有唯一的嵌入式地理数据，重建前不能删除。

使用产品目录现有的 `apply_monthly_update.py` 和 `update_map.py`，先检查当前参数、字段读取方式与实际输入是否一致。执行命令时显式指定工作目录和 Python 环境（通常为该目录的 `.venv/bin/python`，依赖 `openpyxl`、`pandas`）。仅对支持的脚本使用 `--dry-run` 等可选参数。

```bash
<python> apply_monthly_update.py '<本次实际进度表>'
<python> update_map.py --date YYYY-MM
```

合并后核对本期各项目去向、多行映射、历史保留和特殊客户。登记表保持当前产品已确认的字段结构，不因统一 skill 改造工作簿。出现漏项、字段错位或 `[需手工]` 时先处理。

共用脚本按表头检查，产品合并脚本仍可能使用固定列号。如果本次表头插列或重排，先适配读取逻辑并核对结果，不能直接运行旧脚本。

## 验证与发布

- 对照源表检查本期项目、地图去重项目、调度覆盖单位及各层级统计，说明数量差异。核对新项目、更名、多行映射和历史保留；只检查本次存在的场景。
- 状态按产品目录中已确认的规则和证据判定，不因共用流程覆盖另一产品已有的口径。图例、着色、汇总、提示使用相同规则。
- 浏览器打开最终 HTML，检查标题月份、固定来源链接、该产品的全部视图、代表项目提示、下钻与返回及排除区域，查看脚本错误。重建后保留已确认页面范围，不恢复已取消的明细区块。无需因月度数据变化重做视觉设计。
- 对新增或修改的转换逻辑检查同一输入重复执行是否增加记录或改变统计；普通月度刷新可复用既有验证结果。
- 按 [发布规则](publishing.md) 完成已授权发布，并重新读取线上内容核对实际 HTML 或 SHA-256。

回复提供地图链接、进度月份、主要变化和未解决事项。明确区分本地生成、已推送及线上已核验；内容与本次实际完成情况一致。
