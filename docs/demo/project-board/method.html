PRODUCT DESIGN / 方法与样例

一条需求，怎样变成可评审原型

以项目交付为例，把需求、交互和验收放在一起核对。

进入项目看板
需求起点

“我想知道哪些项目有风险，卡在哪项任务。”

使用者是项目管理员和查看进展的协作成员。管理员需要定位未完成工作、分配责任并确认交付；协作成员需要看到一致的状态和验收结果。

本次要解决

进度不能靠手工填写；前置条件没完成就开工；验收口径只留在聊天里。

原型范围

项目看板、新建项目、项目详情、新建任务、任务编辑、验收与退回。

本次演示边界

所有数据均为虚构。操作保存在浏览器；角色切换用于体验界面差异，未连接账户和服务端。

需求 → 规则 → 页面 → 验收

7 条可追踪规则
需求与规则页面如何表达可以怎样验证
R-01 进度可信
按完成任务计算		统计与项目卡片完成一项任务，返回看板核对进度变化。
R-02 找到目标项目
组合筛选取交集		名称、负责人、状态筛选输入不存在名称查看空态，再重置恢复。
R-03 创建有边界
权限、必填、唯一性		新建项目弹窗空表提交、重名、早于当天的日期都应被拦截。
R-04 先完成前置
禁止跳过依赖		发布体验版本任务前置任务未完成，开始按钮禁用并说明原因。
R-05 新任务与项目一致
项目内唯一、日期范围		项目内新建任务截止日期晚于项目日期时，保留输入并报错。
R-06 交付要核对
验收通过或有原因退回		工作台交互联调任务核对全部验收项后完成；或填写原因退回。
R-07 变化可追查
记录状态与原因		任务操作记录退回后查看记录，确认原因与状态一致。

本 Demo 使用的原型能力

01

独立组件与主题

复用组件包的按钮、表单、表格、弹窗和主题机制。浅色、深色使用同一套交互。

02

局部说明绑定控件

右侧卡片有稳定编号。点击定位可找到对应区域，选中的卡片用连线指向控件；弹窗打开时切换到该场景的说明。

03

全局规则留在页底

字段规格、状态规则和跨页面约定集中展示，可独立折叠。界面能直接说明的操作，不在备注里重复。

04

主路径与异常可操作

校验失败保留输入；空结果可重置；依赖不满足时解释原因；验收和退回产生不同结果。

05

用户说明覆盖层

说明正文和页面结构分开保存。本页展示的是静态只读说明；本地编辑需使用支持说明会话的编辑器，点选、框选和保存不在公网开放。

06

规则可回写

规则编号贯穿需求、页面说明和验收结果。评审确认后按页面整理细则、回写需求，再生成研发交付文档。

权限和状态一起决定操作

操作管理员访客状态条件
查看与筛选允许允许所有状态
新建项目 / 任务允许禁止任务日期仍需满足项目范围
编辑任务允许禁止待开始、进行中
提交验收允许禁止进行中
完成 / 退回允许禁止待验收；完成需全部验收项通过

从一个动作看完整结果

打开“工作台交互联调”，核对验收项并完成，再返回“协作工作台改版”查看进度。过程中的规则就在右侧，跨页口径在页底。

体验验收任务

本轮交付

5 个页面共享组件、虚构数据和业务规则。当前是可评审的交互样例，尚未经过业务评审确认，不展示虚构的审批通过记录或研发交付结论。

原型与文档一致

规则 R-01 至 R-07 是本样例的统一口径；各页底部补充本页字段与边界。更改规则时，应同步调整需求对照、受影响页面与验收场景。

先确定解决谁的问题

本 Demo 的业务内容是为公开演示设计的虚构场景。需求起点、范围和规则都在本页公开，可与页面行为逐项核对。

用同一编号表达同一规则

编号用于连接需求、局部说明和验收场景，避免跨页面出现不同口径。表中链接进入实际可操作页面。

区分当前可体验与本地能力

公开页面可体验主题、交互、说明定位和折叠；说明编辑需本地编辑器支持。此 Demo 不声称服务端权限和保存已经实现。

演示设置

操作只保存在当前浏览器，不会发送到服务器。此区域用于体验不同角色和主题。

界面主题

恢复会清除本 Demo 中新增的项目、任务和操作记录，其他站点数据不受影响。
