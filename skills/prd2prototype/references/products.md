# 产品资产选择与接入

生成或迭代原型前先确定产品。集管使用 `assets/products/jg/`，网管使用 `assets/products/wg/`。两套资产分别来自各自现网观测，保留独立布局、样式和交互。未覆盖组件按各自清单补采。

## 选择与依据

| 产品 | 样式与交互 | 查看入口 | 依据范围 |
|---|---|---|---|
| 集管 | `assets/products/jg/jg.css`、`jg.js` | `assets/products/jg/index.html`、`templates/` 内对应页面 | 以包内采集记录和实际覆盖状态为准，未覆盖状态继续补证据 |
| 网管 | `assets/products/wg/wg.css`、`wg.js` | `assets/products/wg/index.html`、`templates/` 内对应页面 | [网管采集清单](wg-ui-inventory.md)，按场景区分实测、演示与未覆盖 |

所有路径均相对本 skill 根目录。先读产品包的组件样例与本轮相关模板，确认类名、token、交互属性，再写页面。不要凭本文件猜测 API。

集管首批观测来自 2026-10-16 的现网浏览：主色 `#0FA081`，顶栏高 `60px`，侧栏宽 `180px`、菜单行高 `56px`，常规列表采用 VXE 表格形态。这些参数只代表已观测场景；具体页面和控件以包内样例、采集记录为准。不能据此宣称所有弹窗、校验状态、响应式尺寸都已观测。

集管已观测的弹层有场景差异：工单新增、网关运行详情使用右侧全高抽屉（`el-drawer`）；资产管理新增使用居中弹窗（`el-dialog`）。模板选择遵从相应场景，不能按“抽屉只能父子下钻”的旧约定统一改成居中弹窗。这些观测不自动覆盖网管或集管未观测的其他新增、详情页。

`conventions.md` 记录产品、所用资产版本或复制日期、相关页面来源、已观测状态与待校准项。纯视觉采集不自动确认权限、默认值、枚举、状态转换、分页业务参数或字段限制；这些仍从用户当前确认的 PRD 读取。

参见 [集管采集清单](jg-ui-inventory.md) 和 [组件接口](jg-components.md)。

## 集管接入

复制 `assets/products/jg/` 到原型目录的同名位置。模板移动到其他层级时，检查其 CSS、JS、字体与图标的相对路径；所有本地资源使用同一个工程修订号。页面业务区使用 `jg-` 类名和包内交互，禁止混入历史 `.btn`、`.table`、`.modal` 等组件样式。

按下列顺序引用；路径随页面深度调整：

```html
<link rel="stylesheet" href="assets/products/jg/jg.css?v=1">
<!-- 页面有需求便签或原型说明时使用辅助层 -->
<link rel="stylesheet" href="assets/skill-extras.css?v=1">
<script src="assets/products/jg/jg.js?v=1"></script>
<script src="data/annotations.js?v=1"></script>
<script src="assets/common.js?v=1"></script>
```

集管业务页面不引用 `common.css`。`common.js` 和 `skill-extras.css` 在集管中只服务需求便签、原型说明与可编辑覆盖层。不要用它们的通用下拉、表格、弹窗或统计卡代替 `jg-` 组件，也不要为满足旧脚本选择器给业务组件补历史类名。

辅助层若依赖历史 token，在原型说明容器或辅助层自身作用域提供兼容值；不要将旧 token 和全局控件样式灌入集管业务区。需求便签可能出现在业务字段旁，其弹层仍属于辅助层。检查 `common.js` 的绑定选择器，确认不会重复绑定集管控件。

`data/annotations.js` 只在不存在时初始化，已有用户内容永不覆写。保持 `window.__ANNO__`、稳定的 `data-anno-id`、`data-anno-rich` 等接口。`annotations.js` 必须早于 `common.js`；生成完成后运行 skill 的可编辑检查脚本，并实际核对便签、说明覆盖内容与业务控件互不干扰。

## 网管接入

先读 [网管组件接口](wg-components.md) 与 [网管采集清单](wg-ui-inventory.md)，再从 `assets/products/wg/templates/` 选对应结构。复制独立网管包，页面使用 `wg-` 类名与 `data-wg-*` 属性，不混用集管包或 `common.css`。

网管已观测的基础参数为顶栏高 `56px`、主色 `#007D7B`、导航激活色 `#0FA081`、背景 `#EFF3F8`、常规控件高 `32px`、普通表格行高 `40px`、常规树节点高 `26px`。拓扑树节点观测为 `32px`，不能把普通树行高套到所有树。主站新增、主站规则新增为 `720px` 居中弹窗，网络设备新增为 `1000px` 工作区内右侧抽屉（顶部 107px、右侧 16px、底部 12px）；终端地址申请新增、巡检任务新增使用全页编辑形态。巡检任务先选巡检类再添加设备，可打开 `1000px`“新增设备”抽屉。按具体场景选型，不把所有新增统一成弹窗。

业务页面基础引用：

```html
<link rel="stylesheet" href="assets/products/wg/wg.css?v=1">
<script src="assets/products/wg/wg.js?v=1"></script>
```

原型说明使用下文的新说明层接入约定。已有说明升级时保留全部用户覆盖内容和稳定 ID。网管业务交互由 `wg.js` 处理；不要为接入说明层给业务控件补旧通用类名。所有资源统一工程修订号。

网管组件中的本地筛选、分页和示例反馈属于预览演示。现网入口可见、实际打开成功、提交校验已验证是不同状态；只看见按钮不能标记其弹窗已校准。

## 网管主题选择

网管包提供 `green`（国网绿）与 `blue`（雅致蓝）主题。雅致蓝为深色界面，页面背景、内容容器、文字、边框、表格和弹层需要一起切换。选择 `body.wg-app[data-wg-theme="blue"]`；绿色使用 `data-wg-theme="green"`，保留原有国网绿样式。

示例入口支持 `?theme=blue` / `?theme=green`，主题选择可在本地保存。交付与截图对照时显式指定主题，避免本地上次选择影响核对。已有项目保留用户当前主题；新页面按本轮指定主题制作。

2026-10-21 已补采雅致蓝基础界面、居中弹窗和设备新增抽屉。校准范围见 [网管采集清单](wg-ui-inventory.md)。已有绿色页面采集不能代替蓝色主题各状态的观测；所有图表、拓扑与日期特有状态尚未全部覆盖。

## 补组件与校准

缺少组件或状态时，先查看现网对应入口、用户截图或已确认设计，记录来源和日期。补充在对应产品包内，保持类名前缀；不要修改历史 `common.css` 使其他产品跟着变化。只获准修改当前原型时，用本原型内的产品扩展文件承接，并记录待回收组件。

没有观测依据的部分明确标为待校准，采用已有产品组件组合进行原型表达。不要写成实测值，也不要从另一个产品复制后宣称一致。功能需要新交互时，区分“本轮确认的新设计”和“现网已有形态”。

同一视口下对照现网与原型，检查顶栏、侧栏、内容留白、字体、筛选密度、表头和行高、操作列、分页、弹窗与已观测状态。测试筛选、重置、选中、翻页、开关弹层和返回链等本轮实际交互；截图看似接近不代表交互已验证。

组件目录与模板使用匿名示例，如“示例站点 A”“示例设备 01”。不复制客户名称、人员、电话、账号、密钥、内网访问凭据或业务记录。采集到的真实数据仅帮助理解结构，不作为新原型的默认内容。现网只读查看授权不等于对现网新增、修改、删除或执行运维操作的授权。

## 右侧与底部说明

新建原型默认接入 [prototype-notes.md](prototype-notes.md)。这一辅助层同时适用于集管和网管，不覆盖各自业务组件样式。`body[data-prototype-notes]` 启用后，`common.js` 保留业务辅助交互并跳过旧编辑 IIFE；覆盖和编辑由 `prototype-notes.js` 统一处理。

在既有资源之后加载 `prototype-notes.css`，并在覆盖文件、产品脚本和 `common.js` 之后加载 `prototype-mark.js`、`prototype-notes.js`。全局说明与宽字段表保留页底浅黄框，局部说明进入右侧。旧原型升级仅移动原说明节点，保留 `data-anno-id`、富文本和全部手改内容。
