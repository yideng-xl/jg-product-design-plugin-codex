# 研发对接版需求说明书 Word 规范

这份规范用于 `prd2prototype` 第 8 步收尾。目标是把已确认的 PRD 细则和 PRD 转成研发可直接阅读的 Word，不依赖个人工作区里的模板文件。

## 输入与口径顺序

生成前必须同时读取：

1. 原型评审后回写的 PRD 细则
2. 原型评审后回写的 PRD
3. 已确认的原型

口径冲突时按以下顺序处理：

- 功能编号、字段、状态、操作、交互和注意事项以 PRD 细则为主。
- 背景、目标、范围、业务规则、权限和非功能需求以 PRD 为主。
- 原型用于核对页面名称、入口、页面间跳转和已确认的展示形态。
- 三者冲突时暂停生成，列出冲突并请用户确认。不要自行选择一版，也不要把原型中的示例数据写成产品规则。

不得改写 PRD 细则和 PRD 源文件。Word 是下游交付物，文件名默认加 `-Codex`；用户确认定稿后再去掉后缀。

## 固定章节

按以下顺序生成：

1. 封面
   - `[产品/版本/主题]`
   - `产品需求说明书`
2. 文档信息
   - 产品经理
   - 交互设计师
   - 研发经理
   - 产品名称
3. 版本记录
   - 版本号 / 修改人 / 修改内容 / 修改时间
4. 一、概述（必填）
   - 需求背景
   - 功能目标
   - 迭代版本
5. 二、业务规则分析
   - 业务流程图
   - 业务规则梳理
6. 三、功能权限说明
7. 四、数据权限说明
8. 五、功能需求（必填）
9. 六、非功能需求说明
   - 7.1 性能需求
   - 7.2 安全需求
   - 7.3 易用性需求
   - 7.4 可靠性需求
   - 7.5 其他说明

文档信息、版本记录中没有真实信息的字段留空或写“待确认”。不得补写人员、时间或版本事实。

## 功能需求表

每个功能编号单独使用一张 2 列表格。左列是字段名，右列是内容。固定 8 行：

| 字段 | 内容来源 |
|---|---|
| 功能编号 | PRD 细则中的编号，按原顺序 |
| 功能名称 | PRD 细则中的正式名称 |
| 功能说明 | 该功能解决什么、展示什么或允许用户做什么 |
| 前置条件 | 权限、数据、状态、入口等前提 |
| 操作流程 | 用户视角的顺序步骤 |
| 功能逻辑 | 规则、状态、计算、异常、边界和数据保留要求 |
| 交互逻辑 | 页面切换、点击、展开、刷新、下钻等交互 |
| 注意事项 | 不做范围、特殊限制、同源口径等补充 |

不要把多个功能编号合并到一张表。不要在表外另起一套功能说明。

每张功能表后必须有且只有 1 个可见空行，包括最后一张功能表。空行要满足：

- 它是正文中的真实空段落，不带 `w:vanish` 隐藏属性。
- 字号 12 pt，单倍行高，段前和段后均为 0。
- 空段落使用宋体。不要只设置“段后间距”模拟空行。
- Word 渲染后，两张表的外边框之间应清楚留出一行空白。

## 版式

- 纸张：A4 纵向。
- 页边距：上 2.54 cm，下 2.54 cm，左 3.17 cm，右 3.17 cm。
- 全文统一宋体。`docDefaults`、正文、标题、表格、页眉页脚都设置宋体；不要只改可见正文运行。
- 封面两行标题：26 pt、加粗、居中。
- 正文：10.5 pt。一级章节标题按 Word 二级标题展示，16 pt、加粗。
- 功能表使用完整边框。左列固定为字段名列，宽度约 2.2 cm；右列占剩余宽度。
- 列表用 Word 原生编号或段内编号。不要用图片替代文字和表格。

跨平台字体设置建议：

- macOS：`Songti SC`
- Windows：`宋体` / `SimSun`
- OOXML 中同时设置 `ascii`、`hAnsi`、`eastAsia`、`cs`，避免中英文分别回退到其他字体。

## 生成方式

优先使用本目录的 `scripts/build_requirements_spec_docx.py`：

```bash
python scripts/build_requirements_spec_docx.py input.json output.docx
```

输入 JSON 的字段结构见脚本顶部说明。脚本从零创建文档，不读取个人目录中的模板。

如果环境已有经用户确认的模板，可以用模板生成，但最终仍要满足本规范。模板只用于版式比对，不是必需依赖。

## 校验

生成后至少执行：

```bash
python scripts/verify_requirements_spec_docx.py output.docx
```

再完成 3 项人工检查：

1. 用 Word 或兼容渲染器导出 PDF，逐页检查全部页面。
2. 核对功能表数量与 PRD 细则中的功能编号数量一致，编号和顺序一致。
3. 核对每张功能表后均有一行可见空白，表格边框没有贴在一起。

只有结构校验通过、逐页渲染无异常，才能报告 Word 已完成。
