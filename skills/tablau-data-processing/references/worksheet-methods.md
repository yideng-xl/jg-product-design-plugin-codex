# 分析与工作表方法 v1.0

本方法从工单、网关和运维对照分析中提炼。按业务问题选工作表；阈值、字段映射、分类关键词和状态口径随项目确认。

## 工作表组织

先独立分析工单、资产/网关、运维，再分析工单与运维、工单与网关；有可靠关联后做三者结合。跨主题重点是批准事项与实际行为是否一致。

| 工作表组 | 用途与必要内容 |
|---|---|
| 00 使用与统计口径 | 来源范围、粒度、连接模式、更新方法、参数、局限 |
| 主题·总览 | 总数、有效数、异常数及比例、缺失与排除数，展示分母 |
| 主题·分维度统计 | 分类、站点、单位、人员、时间段的数量和比例，可定位明细 |
| 主题·问题明细 | 一行对应明确对象，带原字段、判断、阈值和证据 |
| 主题·偏差分析 | 基准来源、有效样本数、中位数、散点与偏差 |
| 明细·日志原文 | 原事件、时间、对象、操作/告警原文和状态 |
| 核对·数据质量 | 重复编号、缺失/倒置、关联覆盖与未匹配清单 |

## 每个问题表的说明

通过可见标题、说明区或仪表板文本，至少展示：

> 数据与范围：哪些表、时间字段、状态和粒度。
>
> 判断依据：比较哪些字段，公式、单位、阈值边界、空值和排除项。
>
> 统计结果：当前筛选下数量、分母、比例及必要交集。
>
> 业务待确认：需检查的流程、现场或日志证据。
>
> 解释：数据支持什么问题，哪些原因尚不能确定。

结果尽量用动态字段；人工结论标明核验批次和范围，刷新后重新检查。业务正文使用业务来源与范围，不写内部目录、脚本或文件行号等过程信息。

## 工单时间质量

先确认是否只统计已结束工单。计划或实际“起止齐全”表示两字段都有值。

| 问题 | 判定与边界 |
|---|---|
| 时间倒置 | 计划结束 < 计划开始；实际结束 < 实际开始。两类分别标明 |
| 时间缺失 | 计划起止齐全，但实际开始或结束任意一项为空 |
| 零耗时 | 计划及实际起止齐全，实际结束 − 实际开始 = 0 |
| 实际耗时过短 | 计划及实际有效，实际耗时 > 0 且 < 可调短阈值 |
| 实际耗时超长 | 计划及实际有效，实际耗时 > 可调长阈值 |
| 计划与实际不符 | 前述异常排除后，实际区间未完整包含于计划区间；细分提前、滞后、部分重合等 |

短长阈值单位一致，校验 `0 ≤ 短阈值 ≤ 长阈值`，边界按表中严格不等式解释。区间分类覆盖：完全提前、完全滞后、左侧部分重合、右侧部分重合、覆盖计划、包含于计划、完全一致。相邻端点相等为相接；是否异常另行约定，不归为正时长重合。

逐项标记可能重合，例如计划倒置与实际缺失。异常总数使用异常对象去重并报告交集；做互斥分组时明确优先级及归属原因，不能直接相加重合指标。

## 分类预判与运维核实

1. 从工单名称及批准工作内容预判分类，保留命中词、字段与依据。先确认内容是否为最终批准范围。
2. 分类示例：调试、巡检、消缺、等级保护、渗透测试、安全防护、其他。`等保` 与 `等级保护` 可归同类；其他关键词结合上下文，否定描述与引用文字不自动证明批准作业。
3. 多类命中可多标签，或登记主分类优先级；“其他”保留人工审阅入口。
4. 用运维和告警验证预判，不用日志中“渗透测试授权”反推工单已批准渗透测试。
5. 偏差单列风险候选，展示工单原文、日志原文、匹配依据、资产、时间及待确认原因。

无日志可能来自漏采、上报延迟或关联不足，告警不直接等于违规。授权通过不等于已执行，授权拒绝不等于实际阻断。姓名相同不直接证明同一人，缺少审批人字段时不推测审批人。

## 授权、操作与告警

按工单分类展示产生的运维与告警：事件次数、涉及工单数、每工单分布、人员/资产、时间和风险候选。高频或异常率同时展示样本数。

二次授权以工单为对象，列编号、名称、站点、批准内容、资产、预判分类、申请/通过/拒绝/其他次数。状态按源定义映射，超时拒绝并入拒绝还是独立列要说明，不能重复相加。重复申请阈值可调。日志无法唯一归单时转入关联覆盖表，不能把申请次数分摊为每张候选工单的已确认次数。

其他日志沿用同一方法，保留各自证据字段：操作内容、命令、端口、地址、文件、设备或告警原文。三主题核对批准资产与实际资产、批准时段与事件时间、预期工作与观察行为；字段不足时说明不能判断。

## 双时长、中位数与散点

| 指标 | 计算 | 缺失与局限 |
|---|---|---|
| 工单实际时长 | 实际结束 − 实际开始，换算为小时 | 起止缺失不计，负值另列异常 |
| 日志计算时长 | 同工单已确认关联日志的最晚时间 − 最早时间 | 无日志未知，单条跨度为 0；跨度不能证明连续作业 |

日志类型、日期范围和关联置信范围写清。仅有候选日志时另标候选时长，不混入已确认基准。

沿用本次工单场景的初始上限为 **24 小时**，做成可调参数；两项分别排除 `>上限` 样本后求同类中位数，等于上限保留。这是项目业务约定，其他项目需确认。一项超限不自动排除另一项有效数据；零耗时是否进入基准另行说明。

每项在去重工单粒度形成一个样本，输出分类有效数、超限数、缺失数、其他无效数、中位数。不在日志联接放大后的明细上直接求中位数。

- 小时偏差 = 该项时长 − 同类该项中位数。
- 相对偏差 = 小时偏差 / 同类该项中位数；中位数为 0 时返回空值并提示。
- 散点每点一张工单，分指标/分类展示；提示含编号、分类、时长、基准、偏差和样本数。偏差视图以 0 为基线，原时长视图以同类中位数为基线。
- 切换日期、状态和类别时检查基准是否按声明更新。无样本或样本不足不显示伪造基线。

虚拟验算：甲类 A 的两项为 2h/1h，B 为 6h/5h，C 为 30h/3h，D 为 24h/26h。以 24h 上限独立排除后，工单中位数为 6h、日志中位数为 3h，各 3 个样本；A 偏差为 −4h/−2h。该例用于核验规则，不是业务结果。
