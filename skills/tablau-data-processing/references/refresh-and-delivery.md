# 更新与交付核验

## Excel：原生提取与更新

保留源连接定义与原始表结构，原始源、分析源都使用提取并在 Tableau 保存 TWBX。包内必须有各提取实际引用的 Hyper；只看扩展名、图标或 XML 标记不够。提取物化计算结果时仍保留可重算公式及源连接。

打开提取型 TWBX 不依赖外部 Excel。提取并不承诺原 Excel 也在包内；有内置 Hyper 与有原 Excel 是不同事项。用户应能在 Tableau 的原始源查看未加分析字段的原始数据。

建立更新映射：

| Excel | 工作表/命名表 | 原始数据源 | 分析源及其他引用 | 本次换路径 | 刷新结果 |
|---|---|---|---|---|---|
| 源文件 | 实际表引用 | 原始·主题 | 全部受影响源 | 是/否 | 成功/失败/未核验 |

### 同路径、同结构覆盖

1. 保存 Excel，保持文件名、工作表/命名表、列名和兼容类型。
2. Tableau 选“数据 → 刷新所有数据提取”。单源可右键 →“数据提取 → 刷新”；多个独立分析源必须一并刷新。
3. 默认全量刷新，核对新行数、时间范围、状态和结果，保存 TWBX。

Excel 修改不会自行触发桌面提取刷新。“自动计算”指原生刷新后重算保存的关联与规则，不意味着无人值守监听文件。

### 换文件或路径

1. 对照映射逐个在数据源页编辑 Excel 连接指向新文件。部分版本需先“编辑数据源”，再打开连接菜单。
2. 检查表引用、表头和类型。改列名、删列、变类型属于结构变更，修复引用并重新核验。
3. 刷新全部受影响提取，保存 TWBX。更改一个原始源连接不会自动更改其他独立分析源路径。

“从文件添加数据…”和“从数据源添加数据…”是追加入口，不用于整表覆盖更新。只有明确追加粒度、稳定键及去重策略后才使用追加或增量，防止重复装入、漏掉历史修改或删除。

## Excel 交付检查

记录实际证据，不只生成“通过”说明：

1. **源与层**：每表原始行列数、时间范围；原始源无新增计算字段；分析字段能追溯公式与源表。
2. **包与模式**：检查 TWBX 内 TWB、Hyper 及实际引用，所需提取启用且存在，无遗漏外部实时 Excel 依赖。原位置作为更新入口保留；临时解压路径不能当稳定更新位置。
3. **刷新**：在 Tableau 刷新全部受影响源，检查成功/失败、时间与结果；抽查新增、修改、删除按策略反映。需变更样本时用隔离副本，不改正式业务值。
4. **计算**：核对总数、去重数、状态分组、关联覆盖、异常边界、筛选与基准；无红色错误或失效字段，至少对照一组手算样本。
5. **独立打开**：在无法访问原 Excel 的环境中，只放入交付 TWBX 并重开，检查原始与分析视图无找源提示。仅把 TWBX 移到另一个目录不能证明独立性；不能真正隔离时如实说明，仅报告已完成的结构和界面核验。
6. **同事更新**：确认具备编辑能力的 Tableau Desktop、同结构 Excel、全部连接入口与刷新说明。只读查看和编辑更新能力分别说明。

大数据量时记录包大小与刷新耗时，不未经授权接入额外业务表或停服务。

## 数据库：实时连接

登记库/模式/表、关联键与读取权限。设为实时，确认未被提取替代；计算放在 Tableau 模型中。先核验粒度与基数，再执行必要查询，避免无关的全表拉取。

验证查询范围与时间，刷新视图确认结果。实时仍可能受缓存影响，不能仅凭模式名称声称绝无延迟；不为核验擅改生产数据库。

分享说明驱动、网络、地址配置与登录要求，不将密码或令牌写入技能、说明或公开仓库。TWBX 不替代数据库连接条件，离线快照另行确认范围和更新时间。

## 故障定位

| 现象 | 检查顺序 |
|---|---|
| 原始源空或红色感叹号 | 连接、表引用、表头、类型、记录范围；别先换成结果表 |
| 刷新后图表不变 | 实际使用源、其他独立连接、提取时间、筛选范围 |
| 数据加倍 | 追加入口、重复导入、联接基数、事件键和粒度 |
| 命名表名称无效 | 用当前连接列出实际引用，核对工作表限定名，不凭显示名拼 XML |
| 中位数不变 | FIXED 与上下文、有效条件、关联放大、静态结果字段 |
| 分享后要找 Excel | 提取是否启用、Hyper 是否打包、残留实时文件源 |

XML 修改仅作有备份的修复，不靠改 `enabled` 标记冒充原生提取。修复后仍须 Tableau 打开、刷新、保存和核验。
