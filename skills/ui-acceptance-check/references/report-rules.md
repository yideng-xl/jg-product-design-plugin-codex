# UI 产品验收报告规则

## 报告标题

```markdown
# UI 产品验收报告 · <需求简称>
```

需求名称无法确认时使用中性名称，不猜项目名或版本号。

## 基本信息

```markdown
- 验收日期：YYYY-MM-DD
- 验收环境：测试、验收或只读生产环境
- 验收范围：实际检查的页面、功能、角色和明确排除项
- 验收依据：UI设计稿、UI说明、UI出图范围、复用依据、通用设计规范
- 操作权限：只读或获准执行的数据操作
- 环境与材料限制：仅在存在限制时填写
```

## 主体表格

按检查表分组，逐项输出：

```markdown
| 检查项 | 验收要素 | 依据 | 结论 | 实际表现与证据 | 问题说明 | 验收备注 |
|---|---|---|---|---|---|---|
| 一致性 | 数值格式与单位保持一致 | UI说明、通用规范 | ⚠️ 部分通过 | 页面 A 显示单位，页面 B 未显示 | 同一数值在两个页面的表达不一致 | 修复后复验两个页面 |
```

写作要求：

- 实际表现写清页面、前置条件和观察结果。
- “通过”也给一句简短证据。
- “不适用”写明本次为什么没有该场景。
- 验收备注只记录处理口径，例如“按默认规范实现”“需求待确认”“修复后复验”“本期明确不验收”。
- 同一问题影响多个页面时合并一条，列出范围，不重复统计。
- 不使用真实组织、人员、行业、系统、项目、版本或业务对象作为示例。

## 问题清单

只汇总表格中的 `❌` 和 `⚠️`，不要新增表格外的问题。每条包含严重程度、复现步骤、预期结果、实际结果和复验口径。

```markdown
| 编号 | 严重程度 | 页面/功能 | 复现步骤 | 预期结果 | 实际结果 | 复验口径 |
|---|---|---|---|---|---|---|
```

严重程度：

- P0：UI 缺陷可能直接导致不可恢复的数据操作或全部页面交互阻断；
- P1：本次 UI 范围内的关键交互无法完成；
- P2：局部功能、边界状态或一致性问题；
- P3：不阻断任务的轻微表现问题。


## 转产品验收确认

疑似业务主流程或数据规则问题单列，不计入 UI 验收结论：

| 页面/功能 | 现象 | 复现步骤 | 需要产品确认的内容 |
|---|---|---|---|

## 测试数据记录

执行过数据操作时记录：

| 测试数据标识 | 执行的操作 | 是否需要清理 | 清理结果 |
|---|---|---|---|

测试数据标识使用脱敏名称，不记录账号、密钥或真实业务数据。
