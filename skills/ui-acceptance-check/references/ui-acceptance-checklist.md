# UI 产品验收表

用于核对实际产品的视觉、交互和反馈是否符合 UI 设计稿、UI 说明、复用依据及通用设计规范。

| 检查项 | 检查要素 |
|---|---|
| 全局规范 | 信息层级是否与设计稿一致，能否引导用户识别主要信息、次要信息和当前任务。 |
| 全局规范 | 页面、弹窗和组件的布局、尺寸、间距、字体、颜色、图标与控件是否还原设计稿，并延续既有样式。 |
| 全局规范 | 页面名称、按钮、状态和提示文案是否清楚、统一、无歧义。 |
| 全局规范 | 业务特有的失败、无结果、不可用和中断状态是否有处理方式。通用异常样式由规范兜底。 |
| 全局规范 | 是否存在需要单独设计或说明的键盘快捷操作；通用键盘行为由规范兜底。 |
| 页面跳转与交互 | 本次 UI 范围内的跳转层级是否符合设计，是否出现不必要的跨页或上下文丢失；不评价端到端业务主流程。 |
| 列表与表格 | 关键业务状态是否有清楚、可区分的视觉标识。 |
| 列表与表格 | 操作列和批量操作在可用、不可用、执行中等状态下是否有明确反馈。通用组件状态由规范兜底。 |
| 页签切换数据保持 | 切回列表页签时，是否保留原查询条件，并按该条件刷新列表数据。 |
| 页签切换数据保持 | 切回表单页签时，是否保留当前填写内容，不重新刷新表单数据。 |
| 列表与表格 | 高频操作是否提供符合既有模式的快捷入口。 |
| 列表与表格 | 批量操作的确认、成功、部分成功和失败反馈是否完整。 |
| 表单与配置 | 必填字段、分组和分步是否还原设计稿，实际布局是否造成明显的填写障碍。 |
| 表单与配置 | 校验失败时是否能定位并高亮具体字段或区域。通用错误样式由规范兜底。 |
| 表单与配置 | 紧凑布局中是否预留错误提示空间，避免遮挡或导致信息错位。 |
| 表单与配置 | 长表单或中断成本较高的配置是否需要暂存或自动保存。 |
| 数据可视化 | 图形、图标和装饰是否服务于信息理解，不干扰数据和状态识别。 |
| 操作反馈 | 提交、导出等操作是否有执行中状态和防重复触发。通用加载规则由规范兜底。 |
| 操作反馈 | 长时间操作是否需要可感知的进度、阶段、剩余时间或后台处理说明。 |
| 导航与树 | 侧边导航是否需要收起、展开，并保持用户当前上下文。 |
| 导航与树 | 节点较多的树形控件是否提供搜索或快速定位。 |
| 输入与多值 | 多值输入是否支持适合数据量的录入、编辑、删除和校验方式。 |
| 导出 | 导出文件名是否包含可识别的业务名称、时间或筛选范围，命名规则是否明确。 |
| 高危操作与确认 | 删除、移除、覆盖等不可逆或高影响操作是否有确认机制。通用确认弹窗由规范兜底。 |
| 高危操作与确认 | 确认文案是否明确操作对象、影响范围和不可恢复后果。 |

## UI 出图范围与验收依据

以下情况可以没有单独设计稿，但实际产品仍需按复用依据实现：

- 与现有成熟页面完全一致；
- 复用通用组件且没有业务差异；
- UI 说明已经把新增规则和差异写清；
- 通用设计规范已经给出完整实现口径。

以下情况不能仅以“复用”为由判定通过：

- PRD 新增了业务状态、分支或影响范围；
- 同类页面没有可直接复用的明确对象；
- 无法从 UI 说明和通用规范确定预期行为；
- 差异会影响用户决策、数据安全或任务完成。

## 不属于 UI 验收

- 业务主流程是否完整；
- 业务规则和计算结果是否正确；
- 接口、数据库和上下游数据是否正确；
- 端到端业务任务是否满足产品目标。

遇到这些问题时只记录现象，转产品验收确认。
