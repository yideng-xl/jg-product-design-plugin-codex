# UI 产品验收

以实际运行的产品为检查对象，由 UI 视角验收视觉还原、交互行为、页面状态和跨页面一致性。

## 必读参考

开始验收前完整读取：

- `references/ui-acceptance-checklist.md`
- `references/report-rules.md`

用户提供了新版检查表时，以用户当前版本为准，并说明本次使用的版本；不要把旧版和新版混在一起。

## 强制前置：取得材料、环境和授权

### 验收依据

按实际可用情况收集：

- UI 设计稿、UI 说明和 UI 出图范围；
- 通用设计规范；
- 可复用的同类页面或组件；
- 评审结论、变更记录和明确不验收项；
- 按需读取 PRD 和产品原型，用于理解页面范围、文案和交互背景。

PRD 和产品原型不是本 skill 的主验收对象。不要据此验收业务主流程、数据逻辑或端到端业务结果。

### 实际产品

至少取得以下一种输入：

- 可访问的测试环境或验收环境链接；
- 用户已经登录的浏览器页面；
- 能覆盖验收范围的完整截图或录屏。

优先使用可操作环境。截图或录屏只能验收已展示的页面和状态，不能据此判定未展示的交互、校验和数据变化已经通过。

### 浏览和数据操作权限

1. 先申请打开实际产品和对应设计材料的查看权限。
2. 浏览、切换页签、打开弹窗等不改变数据的操作，可在获准环境中直接执行。
3. 提交表单、导入、上传、编辑、删除或触发业务流程前，明确确认：
   - 当前是否为测试或验收环境；
   - 可使用的测试账号和权限；
   - 允许创建、修改和删除哪些测试数据；
   - 是否需要在验收后清理数据。
4. 使用虚构且无敏感信息的测试数据。不得把真实账号、人员、组织、地址、密钥或生产数据写入测试表单或报告。
5. 如果只能访问生产环境，除非用户明确授权具体操作和对象，否则保持只读。
6. 权限未开通、链接失效或页面不完整时，说明缺口并请求截图或录屏，不反复尝试绕过权限。

## 验收流程

### 1. 锁定范围

列出本次验收的页面、弹窗、组件、交互、状态、视口尺寸、环境、版本或构建、明确不验收项，以及允许执行的数据操作。范围不明确但可以从材料中可靠推断时先继续，并把推断写入报告；会改变验收结果时再向用户确认。

### 2. 建立验收追踪关系

逐个页面和交互建立：

```text
UI 出图范围 → UI 设计稿/UI 说明 → 可复用页面或组件 → 通用设计规范 → 实际产品
```

产品原型和 PRD 只补充页面上下文，不替代 UI 设计和通用规范。

设计材料没有单独出图时，先判断 UI 出图范围、UI 说明、可复用页面和通用规范是否已经给出实现依据。没有单独出图不等于无需实现。

通用设计规范在验收阶段是预期行为，不是免检理由：

- 实际产品符合规范：判通过，验收备注写“按默认规范实现”；
- 实际产品违反规范：判不通过；
- 当前材料或权限无法触发对应状态：列入待核查。

### 3. 浏览器实查

按用户实际任务路径执行，而不是只浏览页面：

- 核对入口、页面跳转、返回和状态保持；
- 打开页签、弹窗、抽屉、菜单、详情和提示；
- 在授权范围内输入正常值、边界值和错误值；
- 核对提交、等待、成功、失败、空状态和权限限制；
- 核对列表、查询和批量操作的界面与反馈；
- 对照设计稿核对布局、尺寸、间距、字体、颜色、图标、组件和信息层级；
- 核对不同页面间的名称、图标、格式和交互一致性。

每个失败项保留可复现证据：所在页面、前置条件、操作步骤、预期结果和实际结果。可以截图时保留截图；不要在证据中暴露敏感信息。

### 4. 按检查表验收

按 UI 验收检查表核对视觉、交互、反馈、状态和一致性。不漏项，不自行增加检查维度。

问题说明必须围绕当前检查要素，并区分：

- 需求或设计本身未明确；
- 实际产品没有实现；
- 实际产品实现了，但与验收依据不一致；
- 当前权限或材料不足，无法核查。

验收过程中发现疑似业务主流程、数据规则或接口结果问题时，不在本报告里直接判产品不通过。单列“转产品验收确认”，写清现象和复现步骤，交由产品验收处理。

不做检查表之外的体验发散。用户明确要求额外建议时，另设“补充建议”，不计入验收结论。

### 5. 判定

- `✅ 通过`：实际产品与 UI 验收依据一致，对应视觉或交互已实际验证。
- `⚠️ 部分通过`：主体一致，但存在局部视觉、状态或交互缺口。
- `❌ 不通过`：与明确的 UI 验收依据冲突，或问题会阻断对应页面交互。
- `➖ 不适用`：本次范围没有对应场景，并写明原因。
- `❓ 待核查`：材料、权限、环境或测试数据不足，不能强行判定。

### 6. 输出与收尾

按 `references/report-rules.md` 输出验收报告、问题清单和待核查项。

记录本次创建或修改过的测试数据。只有用户授权清理时才删除；清理后在报告中记录结果。

## 边界

- 本 skill 检查已经实现、可访问产品的 UI 视觉和交互。
- 产品经理对业务主流程、业务规则、数据结果和端到端任务的产品验收是另一项工作，不属于本 skill。
- `proto-check` 检查 HTML 原型源码、渲染结果和原型说明，不代替实际产品验收。
- 接口专项、性能压测、安全测试和无障碍专项不属于本 skill。
- 不因看不到材料或页面而编造验收证据。
