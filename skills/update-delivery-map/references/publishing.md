# 预览站发布

从工作区的说明、现有仓库远程和部署配置确认发布位置。常见发布仓库为 `10-productDocs/10-gitlab/prototypesite`，地图置于 `交付地图/`；不要把个人目录、内网地址或凭据作为可分发 skill 的固定配置。

1. 读取发布仓库的工作区状态、当前分支、remote 和 CI 配置。只暂存本次目标地图，不混入其他原型或客户数据。
2. 用户已要求更新既有在线交付地图或明确部署时，沿用已确认的站点与分支发布，无需重复询问。首次发布位置不明时，先生成并验证本地结果，再确认具体仓库、目录、分支和地址。
3. 核对目标文件名后复制已验证的 HTML，比较 SHA-256。提交内容限于本次地图。提交作者信息沿用 Git 配置，不伪造协作作者。
4. 推送被拒时先 fetch 并查看远端差异。工作区干净且没有冲突时可 rebase 后重试；出现冲突时保留双方修改并按具体内容解决。不得强推覆盖远端。
5. `index.lock` 存在时先检查是否有 Git 进程在工作。不能无条件删除锁文件；未确认失效就停止相关写入。
6. 等待 CI 完成后读取实际预览 URL，比对响应 HTML 与本地文件的 SHA-256，再检查页面月份与变更项目。链接给用户时保留可读中文路径；HTTP 请求由客户端做 URL 编码。

内网不可达时保留本地 HTML 和待发布提交，明确说明连接失败及未完成的步骤。不要把 GitHub 推送成功当成内网地图已上线。不要为绕过连接失败擅自改远程、网络配置或另开公开站点。
