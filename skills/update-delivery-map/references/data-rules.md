# 字段、映射与状态规则

## 字段

| 输入列名 | 地图骨架目标列 |
| --- | --- |
| 区域 / 地区 + 客户 | O 列原客户，常见格式 `区域 / 客户` |
| 合同类型 | G 列 |
| 项目分类 | H 列 |
| 标杆项目（集管） | I 列 |
| 交付阶段 | J 列 |
| 交付状态 | K 列 |
| 交付负责人 | L 列 |
| 交付开启日期 | M 列 |
| 交付完成日期 | N 列 |

列号描述的是已有骨架，实际写入前仍应核对表头。网管旧表有 9 个项目字段，集管有 10 个；新表可能在最前面插入“分类”，不能按前 9/10 列截取。

源表使用原始值。清理键的首尾空格即可，不自动模糊匹配、更名或前向填充空客户。若存在合并单元格，先检查合并范围是否证明归属。关键字段为公式时核对缓存值；无缓存值不能按空值导入。

## 客户映射

- 先用骨架“原客户”匹配。相同项目标在多个地理行时，应更新全部行；集管有“省调+超高压”“省调+地调”等情况，需跨 `国网三级调度`、`超高压` 检查。
- 新项目只登记在已核实的地理行。复用既有行时核对省调、地调、覆盖区划和 adcode；修改或新增 adcode 时查权威行政区划资料，不能按名称猜代码。
- 登记行已属于其他项目时先处理冲突，不能覆盖其“原客户”。行号随骨架变化可能漂移，每次都复核行的语义。
- 客户名称增加产品范围后缀时，保留源名称；确认仍是同一调度单位后，用显式别名关联旧落点。
- 月度表未出现的旧客户默认保留旧字段，报告保留清单。缺席不能证明撤销项目。
- 同客户重复记录先逐字段比较。完全一致的地图字段可合并写入一次，登记表仍保留原行；字段冲突时先确认适用项目或版本。分类不同也不能静默覆盖。
- 培训学校等非调度客户不能直接着色整个省调或某个地调。确认采用“仅项目明细”时保留记录，并说明未计入调度覆盖。

## 覆盖状态

已有地图的初始规则：

| 条件 | 覆盖状态 |
| --- | --- |
| 阶段 `4.汇报与验收`，状态 `实施完成` | 运行中 |
| 阶段 `4.汇报与验收`，其他状态 | 试运行 |
| 阶段 `3.实施与验证` | 部署中 |
| 其他阶段或无阶段 | 未覆盖 |

此规则曾按阶段忽略暂停等状态。新表出现“完成”“取消”“升级”等含义时，先核实是否需要修改规则。不要把“完成”等同于“实施完成”，或把“升级”一律视为已运行，除非已有证据或用户确认。

若确认升级项目保留历史覆盖，应保留具体历史状态及来源月份；历史“试运行”不能自动改成“运行中”。升级的本期阶段和日期在项目明细中保留，不能将新阶段与旧状态拼成伪记录。历史未覆盖且本期证据不足的项目仍标为待确认。

状态判定函数、页面图例、统计、提示文字与使用说明一起修改。使用相同判定统计各视图，避免地图着色与汇总数量不同。

沿用已有蒙西和南网排除掩码；本 skill 不重新定义其地理范围。覆盖统计数是调度行/覆盖单位数，跟踪表项目数与地图着色数量不必相等，要能解释差异。
