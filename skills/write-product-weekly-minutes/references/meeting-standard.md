# 产品部周例会标准

本标准由《产品部周例会-会议制度》与 2026 年 7 月、8 月人工定稿纪要共同提炼。会议制度决定议程、主持要求和会后要求；人工定稿决定实际成稿的栏目、排版和压缩方式。

## 一、会议议程与时间

1. 上周闭环确认，2 分钟。会前逐项确认状态；会上只同步结果并追问未完成项。
2. 关键信息分享，3 分钟。部门负责人或业务专家按需分享公司、客户和协同部门的关键信息。
3. 重点工作汇报，18 分钟。按产品方向汇报，成员发言后集中追问。
4. 管理体系建设与执行，6 分钟。汇报体系成果、执行抽查和工作计划，不展开详细过程。
5. 人员培养及团队建设，10 分钟。安排周报复盘、方法讨论和能力进展。
6. 本周闭环确认，1 分钟。主持人逐项确认任务、责任人和完成时间。

管理体系和人员培养两部分不能连续两周没有实质内容。没有重大更新时，相关负责人仍需说明在办事项的状态。

## 二、主持要求

- 汇报先给核心结论。成员发言按“成果、风险、决策”组织，控制在 1.5 分钟内。
- 同一产品方向全部成员讲完后，再集中追问依赖关系、影响和需支持事项，控制在 2 分钟内。
- 部门负责人最后补充，避免先给答案影响成员判断。
- 延期事项要追问原因、已经尝试的处理方式、需要的支持和新的完成时间。
- 以下内容应当场收住：只有动作没有成果结论；只与少数人相关的技术细节；明显超时。
- 远程会议按团队约定开启摄像头。发言结束明确交回主持人。

这些要求用于准备和主持会议。正式纪要只记录结果，不抄入时长、主持提示或会场规则。

## 三、正式纪要固定结构

正文固定为 6 个章节：

1. `一、上周闭环项`
2. `二、关键信息分享`
3. `三、重点工作汇报`
4. `四、管理体系建设与执行`
5. `五、人员培养及团队建设`
6. `六、本周闭环`

不加总标题、日期副标题、基本信息、前言、主持提示、Markdown 标题、表格、引用块或分隔线。章节之间空 1 行。

## 四、各章节写法

### 1. 上周闭环项

每项保持两层：

```text
1、<上周任务>。--<责任人>
--<已完成/部分完成/未完成>。<结论、剩余缺口、新时间>
```

结果只写结论、剩余缺口和下一时间点。版本明细、检查清单和过程记录留在原材料中。会前未取得结果时，第 2 行只保留 `--`。

### 2. 关键信息分享

只收会中明确分享、且会影响部门判断或行动的信息。没有内容时写 `无。`；会前主持稿可留空。

### 3. 重点工作汇报

按 `【网管】`、`【集管】`、`【网安】` 等实际产品方向分组。人员与方向以最近正式纪要和本周材料为准，不把名单固化在 Skill 中。

每位成员固定使用：

```text
1、<姓名>
成果：<已完成产物、已确认结论或已发生结果>
风险和决策：<重大风险、会议决策或“无”>
```

成员有周报且没有重大风险或决策时写 `风险和决策：无`。缺少该成员周报时保留姓名，内容留空。

同一方向所有成员之后写：

```text
追问及建议：
1、<会议形成的判断、要求或建议>
```

没有内容时写 `无。`。跨产品方向的共同要求确实无法归入单一方向时，可以在相关方向之间或之后增加 `网管、集管综合建议`，只写 1 次。

### 4. 管理体系建设与执行

标准子项为产品管理、业务专家、产品设计与 AI 应用。按本周实际材料选择详细写法或合并写法：

```text
1、产品管理：
2、业务专家：
3、产品设计与 AI 应用：
```

3 个方向均无更新时，可以压缩为 1 行。存在会议要求时，在本节末尾增加“追问及建议”。同一成果不要在成员产品成果中重复。

### 5. 人员培养及团队建设

记录周报复盘形成的方法、团队共识、能力进展和明确要求。只记录会议有证据的内容。没有内容时写 `无。`；会前主持稿可留空。

### 6. 本周闭环

每项固定包含 3 个要素：任务、责任人、完成时间。

```text
1、<任务>。--<责任人>，<完成时间>
```

待办只收主持人明确分配或责任人明确承诺的事项。建议、愿望、风险提示和无人承接的讨论不写成待办。

## 五、内容取舍

| 内容 | 写入标准 |
| --- | --- |
| 成果 | 已完成的产物、已确认的结论、已发生的业务结果。压缩成短句，同一人的多个成果用分号分隔。 |
| 风险和决策 | 影响目标、范围、资源、版本、技术路线、发布安排或客户承诺的重大变化，以及需要负责人拍板的事项。 |
| 普通延期 | 只改日期、常规等待、一般进度偏差通常不写入风险和决策。会议专门讨论并形成处理结论时再写。 |
| 追问及建议 | 会中形成、会后仍会影响工作的判断、要求和建议。不能从周报自行推导。 |
| 闭环结果 | 结论、剩余缺口、下一时间点。过程材料不搬入纪要。 |
| 未定讨论 | 写清未定点和下一步。缺少收口时不能写成已确认结论。 |

## 六、语言与发布要求

- 会议纪要是结论记录，不按发言顺序复述。
- 先写结果，再补必要原因和边界。句子保持短。
- 同一事项只出现 1 次。能归入产品方向的内容不要重复放到管理体系或本周闭环说明中。
- 保留必要版本号、日期和量化结果，不堆完整版本清单。
- 数字用阿拉伯数字，中英文之间留空格。
- 正式内容不出现公司名或工具用户名。人员姓名只用于成员汇报、责任人或确有必要的发言事实。
- 会后 24 小时内发布正式纪要。发布前检查本周闭环的任务、责任人和完成时间。
