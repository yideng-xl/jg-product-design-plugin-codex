# 更新集管交付地图

属于插件的“三、产品交付阶段”。服务产品、实施和项目管理人员，查看项目进度、各交付点已登记的运行环境，以及需要补收的信息。

## 输入和事实口径

- 月度《进度跟踪表》提供项目、交付阶段和交付状态；《集管信息一览表》提供环境字段。先列出真实文件名、工作表、表头，核对用户指定的月份。
- 以两份原表为依据。阶段、状态取进度表；部署方式、部署方案、集管版本、操作系统、系统内核、Redis、数据库、加固状态、环境更新时间取信息一览表。
- 原表空值显示“待补收”；“未部署”“不涉及”“已下架”保留原意，不能互相替代。版本和部署方案保留原文，不从升级计划或历史记录推断当前版本，不擅自纠正可疑版本号。
- 月度进度和环境更新时间分别展示。环境表可能晚于进度月份，不能统一标成“截止某月”。环境表最后修改时间只证明记录更新时间。
- 项目键为“地区 / 客户”。合并项目中的 `+` 可拆出多个交付点；各交付点共享原项目阶段和状态，但环境必须分别匹配。展示原表项目名、行号和合并说明。进度项目数按键去重，环境统计按交付点计数。
- 已填齐环境字段不等于实施完成或现场验证通过。地图仍沿用已有三色规则；明细中保留“暂停”等原始状态。

## 执行

1. 读取工作区与产品目录规则。用 [references/workflow.md](references/workflow.md) 定位现有集管地图、脚本和内网发布仓库。确认 Git 状态，保留可回退基线。源表不修改；只更新派生表、数据和页面。
2. 用 [scripts/build_delivery_details.py](scripts/build_delivery_details.py) 读取两份源表并生成 `delivery_details.json`。使用已有 Python 环境（依赖 `openpyxl`），必须传真实路径与 `--date YYYY-MM`。该脚本拒绝重复键、缺列、环境表未匹配交付点；出现错误先核实，不进行模糊匹配或按行号对齐。
3. 检查现有 `apply_monthly_update.py` 的新项目和更名处理，再合并月度数据。新落点优先复用已存在的行政区划行；核对网调、省调、地调和 adcode 后登记。更名映射回原行，不能新增一条重复省调。历史项目从新表消失时保留并单列说明，不能静默计入当期数据。漏项、重复和错配未处理前不发布。
4. 运行现有 `update_map.py --date YYYY-MM`。新版模板已调用本 skill 的 [scripts/render_delivery_panel.py](scripts/render_delivery_panel.py)；检查本地副本与插件脚本是否一致。旧模板可先用该脚本的 `--html`、`--data` 参数插入明细，再把调用接进生成脚本，避免下次重建丢失。脚本不会自动迁移任意 HTML 模板，插入位置不匹配时应检查模板。
5. 保留已有 5 张地图、调度层级、下钻和排除区域。明细支持地区、交付状态、部署方式和 5 项重点字段筛选、缺项筛选、来源说明及 CSV 导出。环境分布与筛选一致，统计分母写明。重点字段缺项、环境未登记和原表冲突分别说明。
6. 按下面的核验要求完成检查。用户要求更新现有交付地图时，按工作区已授权的内部发布方式同步；若用户仅要本地版本，则交付本地文件。只发布集管页面，随后重新获取线上内容，验证关键字段及文件哈希。

## 核验和交付

- 将源表项目数、地图中去重项目键、地图交付点数和环境明细逐项核对。合并项目需解释项目数与交付点数的差异；全部重点字段按信息一览表行号回读核对。
- 至少验证：一个合并项目的两种数据库未串值，一个空环境项目、一个暂停项目、更名项目无重复、新项目已落图；同一输入重复构建不增加记录或页面区块。
- 浏览器实际打开生成页，检查 5 张地图、地调下钻、单项与组合筛选、清空筛选、无结果、分页、来源展开、CSV 内容以及窄屏表格滚动。查看控制台错误，保留实际截图。文件写出或 HTTP 200 都不代表页面正确。
- 回复给出可点击地图链接、更新月份、重点字段覆盖与缺项、仍需确认的原表记录。未上线就明确交付本地版本及阻塞原因。
- 插件仓库只保存通用脚本、规则与合成测试数据。客户交付清单、运行版本清单、源表和生成地图留在业务目录或已授权内网，不随 skill 上传 GitHub。
