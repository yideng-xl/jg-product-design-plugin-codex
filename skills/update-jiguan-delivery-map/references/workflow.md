# 现有集管地图的更新链路

本参考用于已有交付地图的月度维护。先从当前工作区找真实路径；目录编号可能改动，不能用用户消息中的简称直接创建另一套目录。

| 内容 | 相对工作区路径 |
|---|---|
| 集管工作目录 | `10-productDocs/01-集管/30-产品交付进度/` |
| 地图 | `集管产品交付地图.html` |
| 月度输入 | 用户指定的 `*集管*进度*跟踪表.xlsx` |
| 环境输入 | 用户指定的 `*集管信息一览表.xlsx` |
| 地理骨架 / 地图源 | `集管项目进度表_按调度体系.xlsx` |
| 内部预览仓库 | `10-productDocs/10-gitlab/prototypesite/`，只同步 `交付地图/集管产品交付地图.html` |

完整地图依赖现有地理骨架和嵌入式地图数据，本 skill 不重新生成行政区划。模板从旧 HTML 提取 `EMBEDDED_CHINA` 至 `WAN_ORDER` 前的地理数据，因此重建前必须保留旧 HTML。

## 命令参数

在集管目录中使用已有 `.venv/bin/python`；也可用已安装 `openpyxl`、`pandas` 的其他 Python。每次命令显式设置工作目录。

```bash
<python> <skill目录>/scripts/build_delivery_details.py --tracking '<真实月度文件>' --inventory '<真实环境文件>' --date YYYY-MM --output delivery_details.json
<python> apply_monthly_update.py '<真实月度文件>'
<python> update_map.py --date YYYY-MM
```

旧模板尚未集成时，可用下面命令插入环境明细；验证后将相同调用接入生成脚本。重复执行会替换原区块。

```bash
<python> <skill目录>/scripts/render_delivery_panel.py --html '集管产品交付地图.html' --data delivery_details.json
```

## 项目匹配和数据字段

信息一览表按表头读取（忽略表头前的圈号），不用列序号或 `wb.active`。所需列：交付项目（客户）、部署方式、部署方案、集管版本（最新）、操作系统、系统内核版本、Redis版本、数据库及版本、加固及主机防火墙、最后修改时间。

匹配仅统一空白、连字符与网调名称中的“分部”写法。省调名称已带地区时不重复添加地区。合并项目严格按原表 `+` 拆分，不把省调环境复制给同项目下的地调或超高压。脚本无法匹配的新别名必须读取原表确认后补规则。

地图源的“原客户”列标记进度项目键，同一个键可占多个调度行。更名时核对原调度行后替换键；新增时核对已有地理行，不能覆盖另一项目。行政区划映射超出已有骨架时查权威资料或请用户确认。

输出 JSON 只包含本页面使用的字段、来源文件名/工作表/行号和 SHA-256。配置路径、配置内容、人员、联系方式等字段不进入页面。

## 着色口径

| 地图状态 | 原表依据 |
|---|---|
| 运行中 | 阶段 `4.汇报与验收`，状态 `实施完成` |
| 试运行 | 阶段 `4.汇报与验收`，其他状态 |
| 部署中 | 阶段 `3.实施与验证`，任意状态 |
| 未覆盖 | 其余记录 |

这套地图颜色沿用既有统计口径。明细显示原状态，尤其保留暂停记录；不能把颜色标签写成新增的现场核实结论。蒙西及南网 5 省继续排除，各地图层级不自动下穿。

## 内网发布与并行修改

读取发布仓库 remote、分支、CI 配置及工作区授权，沿用已确认的发布目标和地址。本 skill 不预设新的公网发布目标。

多人或多个会话在操作同一仓库时，使用独立克隆或 worktree，只暂存集管目标文件。推送前 fetch 最新远端，再 rebase 自己的提交；有冲突逐项保留双方改动。不能 force push、覆盖整个目录或删除尚在使用的 `index.lock`。

推送触发 CI 后，重新读取实际页面，比较本地与线上哈希并检查关键内容；必要时查 CI 状态。线上检查未完成时，不报告“已上线”。
